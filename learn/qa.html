QA & Testing: interview questions and learning guide

Manual testing, automation and bug reporting

Practise QA & Testing on Padimachi

What you will learn

Testing fundamentals

Testing is asking the product hard questions before customers do.

Testing checks that software does what was promised and does not break what already worked. A test case has a purpose, steps, data and an expected result. Smoke tests quickly check the build is sane, regression tests check old features still work, and acceptance tests confirm the business need. Testers think about normal, boundary and wrong inputs. Good testers report clearly and focus on risk, not on running every possible test.

Interview tip: Explain how you choose what to test first when time is short: by risk and by impact.

Test automation basics

Automate what you will repeat, not everything you can click.

Automation turns stable, repeated checks into scripts that run fast and often. Good candidates are smoke and regression checks on stable features. A framework organises tests, data and reports. Locators must be stable, and waits should be smart rather than fixed sleeps. Flaky tests that pass and fail without code changes waste trust, so they must be fixed or removed. Automation runs in a pipeline so every change is checked.

Interview tip: Say which tests you would not automate and why. That shows judgement.

API testing and bug reports

A good bug report lets a stranger see the bug in two minutes.

APIs let systems talk to each other, so testers check them directly without the screen. A request has a method, address, headers and body, and the response has a status code and data. Tests check codes, data, errors and security basics. A good bug report has a clear title, steps, expected and actual result, environment and evidence like logs or screenshots. Tracking tools follow a bug from new to fixed to closed.

Interview tip: Always include steps, expected result, actual result and evidence in a defect.

Test design techniques

You cannot test everything. Test design is choosing the few cases that find the most bugs.

Test design techniques pick smart test cases from endless inputs. Equivalence partitioning groups inputs that behave the same and tests one from each group. Boundary value analysis tests at the edges, such as the minimum, maximum and just outside. Decision tables list combinations of conditions and the expected result. State transition testing checks how a system moves between states, such as a locked and unlocked account. Exploratory testing uses skill and curiosity, with notes, to find what scripts miss.

Interview tip: Always say the expected result, not just the input, when you write a test case.

Test planning and test cases

A good test plan answers three questions: what will we test, how, and when are we done.

A test plan describes scope, approach, schedule, people, environments and risks. Test scenarios say what to check, and test cases give exact steps, data and expected results. A traceability matrix links each requirement to its test cases so nothing is missed. Entry criteria say when testing can start and exit criteria say when it can stop. A smoke test is a quick check that the build works at all. A regression test rechecks old features after a change.

Interview tip: Write test cases so that another person can run them without asking you.

Performance and load testing

A page that works for one user and breaks for a thousand is not finished.

Performance testing checks speed and stability under expected and extreme use. Load testing uses the expected number of users. Stress testing pushes past the limit to see how the system fails and recovers. Soak testing runs for hours to find slow leaks such as memory. Key measures are response time, throughput, error rate and resource use. Tools such as JMeter or k6 send virtual users. Test in an environment close to production and change one thing at a time.

Interview tip: Talk about numbers: users, response time and error rate, not just that it was slow.

QA in Agile and CI

In Agile, testing is not a phase at the end. It is a habit in every step.

In Agile teams, testers join planning, review stories and test inside the sprint. Shift left means finding problems early, even before code, by questioning requirements. A story has acceptance criteria and a definition of done that includes testing. Automated checks run in a CI pipeline on every change so failures show within minutes. Bug triage sets priority and severity so the team fixes the right things first. Clear bug reports with steps, result and evidence save everyone time.

Interview tip: Say how you handle a late change: re-check risk, test the key paths and tell the team what was not covered.

Mobile and cross-browser testing

Your users have thousands of phones. Your website must work on the ones they actually own.

Mobile and cross-browser testing checks that an app or site works on different devices, screen sizes, operating systems and browsers. Choose a test matrix from real usage data, covering the most common devices and one or two old ones. Check layout, touch targets, rotation, slow networks, interruptions such as calls and low battery. Tools such as Appium automate mobile tests and cloud device labs give access to many devices. Real device checks catch issues emulators miss.

Interview tip: Say how you choose which devices to test: use analytics, not guesses.

Interview questions and sample answers

What is the difference between severity and priority?

Severity is how badly the defect hurts the product. Priority is how soon it should be fixed, which also depends on business needs.

How do you decide what to test when time is short?

Test by risk: critical user journeys and recently changed areas first, then regression on related features, and tell stakeholders what was not covered.

What makes a good bug report?

A clear title, exact steps, expected and actual result, the environment and evidence such as logs or screenshots so anyone can reproduce it.

Which tests would you not automate?

One time checks, fast changing screens, exploratory and usability testing, where the cost of automating is higher than the value.

What is the difference between verification and validation?

Verification checks we built the product right against the specification. Validation checks we built the right product for the user's need.

What goes into a good bug report?

A clear title, steps to reproduce, expected and actual result, environment, severity and evidence such as a screenshot or log.

What is the difference between smoke and regression testing?

Smoke testing is a quick check that the build basically works. Regression testing checks that old features still work after changes.

What is boundary value analysis?

Testing at and around the limits of an input range, such as 17, 18 and 19 for an age limit of 18.

When should you automate tests?

Automate stable, repetitive, high-value checks like regression and API tests. Keep exploratory and one-time checks manual.

What is the difference between severity and priority in a defect?

Severity is the technical impact. Priority is how soon the business wants it fixed.

What is an API test and what do you check?

Sending requests to endpoints and checking status code, response body, headers, error handling and speed.

How do you test a login page?

Valid and invalid credentials, empty fields, password rules, lockout, forgot password, session timeout, security and different browsers.

What is a regression test and why is it needed?

A regression test rechecks existing features after a change to make sure nothing broke. Because it repeats often, it is a good candidate for automation.

What is the difference between load testing and stress testing?

Load testing uses the expected number of users to check normal performance. Stress testing goes beyond the limit to see how the system fails and recovers.

Senior and lead interview questions

How do you build a test strategy for a new product?

Understand risks, define test levels, choose automation targets, set environments and exit criteria.

How do you decide what to automate?

Automate stable, repeated, high-value tests; keep exploratory and one-off tests manual.

How do you decide a release is ready?

Check exit criteria, open defects by severity, test coverage, risks and stakeholder sign-off.

How do you build a quality culture in engineering?

Shift testing left, review requirements, share ownership of quality and track escaped defects.

How do you manage a QA team and vendor testers?

Set clear scope and metrics, review work, share knowledge and run regular syncs.

How do you reduce flaky tests?

Find root causes, fix waits and data, isolate tests, quarantine and track flake rate.

How do you measure QA effectiveness?

Use escaped defects, defect detection rate, test coverage, cycle time and customer issues.
