Cloud & DevOps: interview questions and learning guide

Linux, pipelines, containers and cloud basics

Practise Cloud & DevOps on Padimachi

What you will learn

Linux and shell basics

The terminal is a very fast steering wheel. You must learn what each turn does.

Most servers run Linux, and engineers work through the command line. Core skills are moving through folders, reading files, searching with grep, checking processes and disk, and editing configuration. Permissions decide who can read, write or run files. Services are started and checked with the system service manager, and logs show what went wrong. Scripts and scheduled jobs automate repeated tasks. Careful habits such as checking before deleting prevent outages.

Interview tip: Show that you read logs first and change one thing at a time.

CI/CD and DevOps practices

DevOps is making the road from code to customer short, safe and boring.

DevOps joins development and operations so software is built, tested and released in small safe steps. Continuous integration builds and tests every change. Continuous delivery prepares the release and deployment can be automatic. Small releases, version control, automated checks and quick rollback reduce risk. Monitoring and alerts tell the team when something breaks, and blameless reviews turn failures into fixes.

Interview tip: Say how you would roll back, not only how you would deploy.

Containers and infrastructure as code

If the setup lives only in someone's memory, it is a risk. Put it in code.

Containers package an application with what it needs so it runs the same everywhere. Images are built from a recipe and run as containers. An orchestrator such as Kubernetes starts, restarts and scales many containers. Infrastructure as code describes servers, networks and storage in files, so environments can be created and reviewed like software. Cloud providers rent computing by use, so cost control and security settings matter from day one.

Interview tip: Mention cost and security together when you speak about cloud design.

Interview questions and sample answers

Walk me through a CI/CD pipeline.

A commit triggers a build and automated tests, then the artifact is deployed to a test stage, and after checks to production, with monitoring and a way to roll back.

What is the difference between an image and a container?

An image is the saved, read-only recipe. A container is a running instance started from that image.

A service is down. What are your first steps?

Check the status and logs, find recent changes, restore service first, often by rolling back, communicate to stakeholders and review the cause afterwards.

Why use infrastructure as code?

It makes environments repeatable and reviewable, keeps changes in version control and removes manual drift between environments.

What is the difference between IaaS, PaaS and SaaS?

IaaS gives virtual machines and networks, PaaS gives a platform to run code, and SaaS gives a finished application.

What is a container and how is it different from a virtual machine?

A container shares the host operating system kernel and is light and fast. A VM carries a full guest operating system.

What is CI/CD?

Continuous integration builds and tests every change automatically. Continuous delivery deploys it to environments with little manual work.

What does the principle of least privilege mean?

Give every user and service only the permissions needed for the job, and no more.

What is a load balancer?

It spreads incoming traffic across several servers so no single one is overloaded and the service stays available.

How do you check why a Linux server is slow?

Use top for CPU and memory, df for disk, iostat for disk activity and logs for errors, then find the process behind the load.

What is Infrastructure as Code?

Describing servers and networks in files such as Terraform so they can be versioned, reviewed and recreated reliably.

What is the difference between horizontal and vertical scaling?

Vertical scaling makes one machine bigger. Horizontal scaling adds more machines behind a load balancer.

Senior and lead interview questions

How do you design a highly available and cost-aware cloud architecture?

Use multiple zones, autoscaling, managed services and monitoring, and track cost by tag and budget alerts.

How do you run a blameless post-incident review?

Build a timeline, find contributing causes, avoid blaming people, assign actions with owners and share lessons.

How do you set SLOs and manage error budgets?

Pick user-focused indicators, set targets, track error budget and slow releases when it is spent.

How do you plan a cloud migration?

Assess workloads, pick a strategy such as rehost or refactor, pilot, migrate in waves and plan rollback.

How do you secure a cloud environment?

Use least privilege IAM, network segmentation, encryption, secrets management, logging and regular reviews.

How do you manage on-call health in a team?

Share the rotation fairly, reduce noisy alerts, write runbooks, compensate and review burnout.

How do you drive infrastructure as code adoption?

Start small, set module standards, review changes in pull requests and automate checks.
